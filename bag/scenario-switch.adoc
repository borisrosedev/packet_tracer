= Scénario


== Introduction

Avec votre infrastructure comprenant trois switches de niveau 2, un switch de niveau 3 et deux routeurs en failover, 

Quelques recommandations pour configurer et sécuriser les accès avec les utilisateurs, les privilèges et la gestion de la haute disponibilité :



== 1. Configuration des Privilèges Utilisateur sur les Switches et Routeurs


=== Définir des utilisateurs avec des niveaux de privilèges adaptés :


=== Administrateurs réseau (niveau 15) : Accès complet pour configurer les switches et routeurs.


=== Moniteurs ou techniciens (niveaux 1 à 5) : Accès limité pour vérifier l'état des équipements sans modifier la configuration.
Par exemple, sur tous les équipements :

[source, bash]
----
Switch(config)# username admin privilege 15 secret AdminPass
Switch(config)# username monitor privilege 5 secret MonitorPass
----

Utiliser des niveaux de privilèges intermédiaires sur les switches de niveau 2 :

Par exemple, vous pourriez accorder aux utilisateurs de niveau 5 la possibilité d’exécuter des commandes show pour surveiller les interfaces et les VLANs sans avoir accès aux commandes de configuration :

[source, bash]
----
Switch(config)# privilege exec level 5 show vlan
Switch(config)# privilege exec level 5 show ip interface brief
----



== 2. Configurer SSH pour un accès sécurisé

Configurez SSH sur les switches et routeurs pour assurer une connexion sécurisée :


=== Configurer SSH sur les équipements :

Nommez chaque switch avec une convention identifiable (par exemple, SW1-Marketing, SW2-Finance, etc.), et utilisez un domaine commun.

[source, bash]
----
Switch(config)# hostname SW1-Marketing
Switch(config)# ip domain-name entreprise.com
Switch(config)# crypto key generate rsa
----


=== Configurer l'authentification par SSH :

Sur chaque équipement, configurez les lignes VTY pour n’accepter que SSH :

[source, bash]
----
Switch(config)# line vty 0 4
Switch(config-line)# transport input ssh
Switch(config-line)# login local
----



== 3. Configurer les Routeurs en Mode Failover

Avec deux routeurs en failover, vous pouvez utiliser:
[%step]
* le protocole HSRP (Hot Standby Router Protocol), 
* VRRP (Virtual Router Redundancy Protocol),
* GLBP (Gateway Load Balancing Protocol) pour assurer la redondance de la passerelle par défaut.


=== Configurer HSRP (exemple sur deux routeurs) :

=== Sur le Routeur Principal :

[source, bash]
----
Router1(config)# interface g0/1
Router1(config-if)# ip address 192.168.1.2 255.255.255.0
Router1(config-if)# standby 1 ip 192.168.1.1       # IP virtuelle de la passerelle
Router1(config-if)# standby 1 priority 110         # Priorité plus élevée
Router1(config-if)# standby 1 preempt
----


=== Sur le Routeur de Secours :

[source, bash]
----
Router2(config)# interface g0/1
Router2(config-if)# ip address 192.168.1.3 255.255.255.0
Router2(config-if)# standby 1 ip 192.168.1.1       # Même IP virtuelle
Router2(config-if)# standby 1 priority 90          # Priorité inférieure
Router2(config-if)# standby 1 preempt
----

=== Explication :

L’adresse IP virtuelle 192.168.1.1 sera utilisée comme passerelle par défaut pour les équipements.

=== ...

Le routeur avec la priorité la plus élevée (ici, Router1) sera actif par défaut. Si Router1 échoue, Router2 prend le relais.

== 4. Gestion Centralisée et Surveillance

Pour simplifier la gestion et la surveillance :


=== ...

Centralisez les logs (Syslog) et la synchronisation de l’heure (NTP) sur un serveur commun pour tous les switches et routeurs.

=== ...

Configurez SNMP sur chaque switch et routeur pour surveiller l’état des équipements depuis un serveur de gestion central.

=== ...

Utilisez des ACLs pour restreindre l'accès aux services depuis des sous-réseaux spécifiques.

=== ...

Avec cette configuration, vous disposerez d'une infrastructure redondante, sécurisée et facile à surveiller, avec des contrôles d’accès bien définis pour chaque type d’utilisateur.

=== ...

Si vos routeurs possèdent des sous-interfaces correspondant aux VLANs, cela signifie que vous utilisez le routage inter-VLAN pour permettre la communication entre les différents VLANs. 

=== ...


Dans cette configuration, chaque sous-interface sur les routeurs agit comme la passerelle pour un VLAN spécifique, ce qui simplifie le routage entre les VLANs.


=== Configurer les Sous-Interfaces pour le Routage Inter-VLAN

Sur les routeurs, chaque sous-interface est associée à un VLAN et a sa propre adresse IP, servant de passerelle pour les dispositifs dans ce VLAN. Voici comment configurer cela :

Exemple de Configuration des Sous-Interfaces pour les VLANs
Imaginons trois VLANs :

VLAN 10 : 192.168.10.0/24
VLAN 20 : 192.168.20.0/24
VLAN 30 : 192.168.30.0/24
Sur votre routeur principal :

Configurer une sous-interface pour chaque VLAN :

[source, bash]
----
Router(config)# interface g0/0.10
Router(config-subif)# encapsulation dot1Q 10         # Associe la sous-interface au VLAN 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface g0/0.20
Router(config-subif)# encapsulation dot1Q 20         # Associe la sous-interface au VLAN 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface g0/0.30
Router(config-subif)# encapsulation dot1Q 30         # Associe la sous-interface au VLAN 30
Router(config-subif)# ip address 192.168.30.1 255.255.255.0
----


Chaque sous-interface (g0/0.10, g0/0.20, et g0/0.30) est configurée avec une adresse IP correspondant à son VLAN, et la commande encapsulation dot1Q <VLAN_ID> associe chaque sous-interface à un VLAN spécifique.


== Impact de cette Configuration avec le Routage Inter-VLAN et les ACLs

=== Routage Inter-VLAN :

Avec cette configuration, le routeur peut acheminer le trafic entre les VLANs. 

=== ...

Par exemple, un dispositif dans le VLAN 10 peut communiquer avec un dispositif dans le VLAN 20 en passant par le routeur.


=== ...

Cela élimine le besoin de définir une passerelle par défaut au niveau du switch pour le routage entre VLANs, car le routeur gère tout le routage inter-VLAN.


=== Accès Sécurisé via SSH et ACLs :

Vous pouvez définir des ACLs sur les sous-interfaces pour contrôler quel trafic est autorisé entre les VLANs, ce qui est important pour sécuriser l'accès entre différents segments du réseau.

=== ...

Par exemple, si vous voulez limiter l’accès aux switches uniquement depuis des sous-réseaux de gestion, vous pouvez créer une ACL pour restreindre le trafic SSH à certains VLANs.

=== ...

Exemple d'ACL pour Limiter l'Accès SSH aux VLANs de Gestion
Si vous voulez autoriser l'accès SSH à vos switches et routeurs uniquement depuis un VLAN spécifique (par exemple, VLAN 10 en tant que VLAN de gestion) :

== Créer une ACL sur le routeur principal :

[source, bash]
----
Router(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq 22


Router(config)# access-list 110 deny tcp any any eq 22
----

=== ...

Cette ACL permet uniquement les connexions SSH (port 22) provenant du VLAN 10. 

=== ...

Toute autre tentative de connexion SSH depuis d'autres VLANs sera bloquée.


=== Appliquer l'ACL à chaque sous-interface :

[source, bash]
----
Router(config)# interface g0/0.10
Router(config-if)# ip access-group 110 in
----

=== ...

Cette configuration garantit que seul le VLAN de gestion (VLAN 10) peut accéder aux dispositifs via SSH, renforçant ainsi la sécurité.



=== ...

Lorsqu'on utilise deux routeurs en failover avec des sous-interfaces pour chaque VLAN, il est important de configurer une IP virtuelle pour chaque VLAN. 


=== ...

Cela permet aux dispositifs dans chaque VLAN d'avoir une passerelle par défaut unique, même si le routeur principal devient indisponible.

=== ...

Dans une configuration de failover avec deux routeurs, les protocoles comme HSRP (Hot Standby Router Protocol), VRRP (Virtual Router Redundancy Protocol) ou GLBP (Gateway Load Balancing Protocol) sont utilisés pour créer ces adresses IP virtuelles. 

=== ...

Ces protocoles permettent de configurer une adresse IP virtuelle par VLAN, qui bascule automatiquement vers le routeur secondaire en cas de panne du routeur principal.

=== ...

Exemple de Configuration HSRP avec des Sous-Interfaces pour chaque VLAN

=== Supposons que nous avons trois VLANs :

VLAN 10 : 192.168.10.0/24
VLAN 20 : 192.168.20.0/24
VLAN 30 : 192.168.30.0/24

Les deux routeurs seront configurés avec des sous-interfaces et des adresses IP virtuelles pour chaque VLAN.


== 1. Configuration du Routeur Principal (Router1)
Configurer les sous-interfaces pour chaque VLAN avec HSRP :

[source, bash]
----
Router1(config)# interface g0/0.10
Router1(config-if)# encapsulation dot1Q 10
Router1(config-if)# ip address 192.168.10.2 255.255.255.0
Router1(config-if)# standby 10 ip 192.168.10.1       # IP virtuelle pour VLAN 10
Router1(config-if)# standby 10 priority 110
Router1(config-if)# standby 10 preempt

Router1(config)# interface g0/0.20
Router1(config-if)# encapsulation dot1Q 20
Router1(config-if)# ip address 192.168.20.2 255.255.255.0
Router1(config-if)# standby 20 ip 192.168.20.1       # IP virtuelle pour VLAN 20
Router1(config-if)# standby 20 priority 110
Router1(config-if)# standby 20 preempt

Router1(config)# interface g0/0.30
Router1(config-if)# encapsulation dot1Q 30
Router1(config-if)# ip address 192.168.30.2 255.255.255.0
Router1(config-if)# standby 30 ip 192.168.30.1       # IP virtuelle pour VLAN 30
Router1(config-if)# standby 30 priority 110
Router1(config-if)# standby 30 preempt
----


=== ...


Chaque sous-interface est configurée avec une adresse IP réelle (par exemple, 192.168.10.2 pour le VLAN 10) et une IP virtuelle partagée entre les deux routeurs (par exemple, 192.168.10.1).

=== ...

standby <VLAN_ID> ip <IP_VIRTUELLE> définit l'IP virtuelle que les dispositifs du VLAN utiliseront comme passerelle par défaut.


=== ...


priority 110 et preempt indiquent que Router1 est le routeur actif par défaut.


== 2. Configuration du Routeur de Secours (Router2)
Configurer les mêmes sous-interfaces avec des priorités plus faibles pour qu’il devienne le routeur de secours :

[source, bash]
----
Router2(config)# interface g0/0.10
Router2(config-if)# encapsulation dot1Q 10
Router2(config-if)# ip address 192.168.10.3 255.255.255.0
Router2(config-if)# standby 10 ip 192.168.10.1
Router2(config-if)# standby 10 priority 90
Router2(config-if)# standby 10 preempt

Router2(config)# interface g0/0.20
Router2(config-if)# encapsulation dot1Q 20
Router2(config-if)# ip address 192.168.20.3 255.255.255.0
Router2(config-if)# standby 20 ip 192.168.20.1
Router2(config-if)# standby 20 priority 90
Router2(config-if)# standby 20 preempt

Router2(config)# interface g0/0.30
Router2(config-if)# encapsulation dot1Q 30
Router2(config-if)# ip address 192.168.30.3 255.255.255.0
Router2(config-if)# standby 30 ip 192.168.30.1
Router2(config-if)# standby 30 priority 90
Router2(config-if)# standby 30 preempt
----


Router2 a des priorités plus faibles (priority 90), donc il devient le routeur de secours pour chaque VLAN. Il prendra le relais si Router1 devient indisponible.
