= Redonder un switch

== Introduction

Redonder votre switch cœur de réseau est une étape cruciale pour améliorer la résilience et la disponibilité de votre infrastructure réseau. 
1. Évaluer vos besoins
Identifiez les risques actuels : Quels sont les impacts en cas de panne de votre switch principal ?
Estimez le niveau de disponibilité nécessaire : 99.9 % (quelques minutes de panne par an) ou 99.99 % (quelques secondes de panne) ?
Préparez un budget pour le matériel, la configuration et la maintenance.
2. Choisir une architecture de redondance
Plusieurs approches sont possibles selon vos besoins :

a. Stacking
Si vos switches supportent le stacking (comme Cisco StackWise, Aruba VSF, ou Juniper Virtual Chassis), configurez plusieurs switches pour fonctionner comme une seule unité logique.
Avantages : Simplicité de configuration et une seule adresse IP de gestion.
b. Virtual Chassis ou VSS (Virtual Switching System)
Permet de virtualiser deux switches pour qu'ils fonctionnent comme un seul. Cela assure une tolérance aux pannes tout en simplifiant la gestion.
c. Redondance matérielle classique
Installez deux switches distincts et configurez des liens redondants entre eux.
Utilisez des protocoles de redondance comme Spanning Tree Protocol (STP) ou Rapid STP pour éviter les boucles réseau.
3. Configurer des liens redondants
EtherChannel (ou LAG - Link Aggregation Group) :
Agrégez plusieurs liens physiques entre vos switches et vos équipements pour augmenter la bande passante et assurer une redondance au niveau des liens.
Protocole de gestion des liens :
Configurez LACP (Link Aggregation Control Protocol) pour une gestion dynamique des liens redondants.
4. Assurer la redondance des passerelles
Configurez une redondance au niveau de la passerelle pour éviter les interruptions en cas de panne de votre switch cœur :
HSRP (Hot Standby Router Protocol), VRRP (Virtual Router Redundancy Protocol), ou GLBP (Gateway Load Balancing Protocol) pour des passerelles IP redondantes.
5. Tester et monitorer
Tests de basculement :
Déconnectez un switch ou un lien pour vérifier que le trafic est bien redirigé vers les équipements redondants.
Supervision :
Utilisez des outils comme Nagios, PRTG, ou Zabbix pour surveiller les performances et la disponibilité de vos switches.
6. Planifier la maintenance
Assurez-vous que les firmwares sont à jour sur vos switches.
Vérifiez régulièrement l'état des liens et les configurations pour éviter les mauvaises surprises.
Exemple d’architecture :
Deux switches redondants avec liens agrégés, configurés en VSS, et reliés à plusieurs équipements en utilisant LACP et VRRP pour la redondance.

Si vous avez des modèles spécifiques de switches, je peux vous guider pour leur configuration exacte.

Oui, il est tout à fait possible de redonder votre réseau et d’y intégrer un load balancer en même temps. Cela permet de répartir le trafic entre plusieurs chemins tout en assurant une haute disponibilité. Voici les concepts et étapes nécessaires pour y parvenir.

1. Concepts clés à comprendre
Redondance réseau : Garantit que si un chemin ou un appareil tombe en panne, le trafic est redirigé via un chemin alternatif.
Load balancing (équilibrage de charge) : Répartit le trafic entre plusieurs chemins ou dispositifs pour optimiser les performances et éviter la surcharge.
Protocoles et technologies clés :
HSRP/VRRP/GLBP pour les passerelles redondantes.
LACP (EtherChannel) pour l’agrégation de liens.
GLBP (Gateway Load Balancing Protocol) pour répartir la charge entre plusieurs passerelles, en plus de la redondance.
2. GLBP pour redondance et load balancing
Si vous souhaitez équilibrer la charge entre plusieurs switches et offrir une passerelle virtuelle, le Gateway Load Balancing Protocol (GLBP) est la meilleure option.

Pourquoi GLBP ?
Contrairement à HSRP ou VRRP, qui offrent uniquement une redondance active/standby, GLBP permet d’utiliser toutes les passerelles disponibles de manière simultanée.
Il répartit la charge en utilisant des algorithmes comme le round-robin ou le poids.
Configuration GLBP :
Configurez GLBP sur vos switches :
Switch 1 :
bash
Copier le code
interface vlan 10
ip address 192.168.1.2 255.255.255.0
glbp 1 ip 192.168.1.1
glbp 1 priority 120
glbp 1 preempt
Switch 2 :
bash
Copier le code
interface vlan 10
ip address 192.168.1.3 255.255.255.0
glbp 1 ip 192.168.1.1
glbp 1 priority 100
glbp 1 preempt
Explications :
glbp 1 ip 192.168.1.1 : Crée une passerelle virtuelle partagée.
priority : Détermine quel routeur est le Active Virtual Gateway (AVG).
Les deux switches deviennent des Active Virtual Forwarders (AVF) et se partagent le trafic.
